# Brouillon landing (static site)

Pure static HTML/CSS, no framework, no JavaScript, no cookie, no third-party request.
Generated by one dependency-free Node script (Node 18+). Hosting target: Cloudflare Pages.

## Layout

```
site/
  scripts/build.mjs        generator (templates + copy -> site/dist)
  scripts/check.mjs        post-build checks (HTML, links, SEO lengths, JSON-LD, weight, contrast, externals, forbidden names)
  scripts/forbidden.mjs   forbidden third-party names (shared by check.mjs and the tests)
  scripts/build.test.mjs   automated tests of the build (ok / manifest missing / wrong hash ...)
  src/content.mjs          all copy, EN + FR (stable structure)
  src/style.css            design tokens + styles (dark and light token sets; system theme by default, no-JS picker)
  public/                  copied as-is (fonts, OG image). public/downloads/ is written by the release pipeline
  test/make-fixture.mjs    creates a SAMPLE manifest + fake artifact (never used for production)
  wrangler.toml            Cloudflare Pages project (no credentials)
  dist/                    build output (git-ignored)
```

URLs: EN at `/`, FR at `/fr/`. Pages: home, download (`/download/`, `/fr/telecharger/`), privacy,
changelog, plus `/llms.txt`, `/llms-full.txt`, `/robots.txt`, `/sitemap.xml`, `/404.html`, `_headers`, `_redirects`.

## Commands

```
node site/scripts/build.mjs            # build -> site/dist (fails loudly if the manifest/artifacts are wrong)
node site/scripts/check.mjs            # verify the build
node --test site/scripts/build.test.mjs

# with the sample fixture instead of the real manifest:
node site/test/make-fixture.mjs
DOWNLOADS_DIR=site/test/fixture-downloads node site/scripts/build.mjs
```

On PowerShell: `$env:DOWNLOADS_DIR="site/test/fixture-downloads"; node site/scripts/build.mjs`.

## Configuration (environment variables, read once in `build.mjs`)

| Variable | Default | Effect |
|---|---|---|
| `SITE_URL` | `https://brouillon.rochetta.fr` | The ONLY source of absolute URLs (canonical, hreflang, Open Graph, JSON-LD, sitemap, llms.txt). The domain is provisional: change it here only. |
| `REPO_URL` | empty (TODO) | Public repository. When unset, pages say "link to be added" and no GitHub link is invented. When set, adds repository + issues links and JSON-LD `sameAs`. |
| `INDEXABLE` | `false` | `false`: `<meta name="robots" content="noindex,follow">` on every page, `X-Robots-Tag: noindex` in `_headers`, no `Sitemap:` line in robots.txt (sitemap.xml exists but is not submitted). `true`: all of that is removed. |
| `DOWNLOADS_DIR` | `site/public/downloads` | Folder holding `build-info.json` and the artifacts (tests/fixtures only). |
| `OUT_DIR` | `site/dist` | Output folder. |

Going live checklist: set `SITE_URL` to the final domain, set `REPO_URL`, build with `INDEXABLE=true`,
then submit `sitemap.xml` in Search Console / Bing Webmaster Tools.

## Download block and the manifest

Version, build number, build date (UTC), SHA-256, size, platform, signed flag are read ONLY from
`site/public/downloads/build-info.json` at build time:

```json
{"product":"","version":"","build":"","build_date_utc":"","git_commit":"","channel":"","platform":"","min_os":"",
 "artifacts":[{"kind":"","file":"","size_bytes":0,"sha256":""}],"signed":false,"license":"","author":""}
```

The build FAILS (exit 1, clear message) if the manifest is missing or invalid, a field is absent, an artifact
file is absent, its size differs, or its recomputed SHA-256 differs from the manifest.
Cloudflare Pages limits single files to 25 MiB: larger artifacts need another host (then adapt the links).

## Fonts

Inter (variable, latin subset) and JetBrains Mono (Regular, latin subset), SIL OFL 1.1, self-hosted in
`public/assets/fonts/` (licences alongside). Sources: github.com/rsms/inter v4.1, github.com/JetBrains/JetBrainsMono v2.304.
System font fallback is in the CSS.

## Notes

- No inline script and no inline style, so the CSP in `_headers` is `script-src 'none'; style-src 'self'`.
- The editor mockup is pure HTML/CSS and is labelled as a design preview.
- Nothing here deploys anything. Deploy later with `wrangler pages deploy` from `site/` (not run by this project's scripts).
- Theme: follows `prefers-color-scheme` by default. The header picker (system / light / dark) is a radio group driven by `:root:has(#th-*:checked)`, so it needs no JavaScript, cookie or storage. Trade-off: the choice is NOT persisted and resets to the system theme on each navigation (a static page without JS/cookie cannot remember it); `theme-color` and the favicon follow the system theme only. Browsers without `:has()` hide the picker and keep the system theme. Contrast of both token sets is checked by `scripts/check.mjs`.
